Material de consulta

Material de consulta del método con el que se construye la capa de conocimiento: vocabulario, tipos de documento, relaciones, una plantilla para empezar y la lista de comprobación previa a la revisión.

Plantilla

Una spec, entera

Un fichero Markdown con cabecera YAML y cuatro secciones. Cópiala, cambia los valores y pásale la validación.

---
id: DOM-RISK-001
type: knowledge
layer: domain
title: "Cálculo de riesgo de mercado (VaR)"
status: draft
confidence: low
version: "0.1.0"
owner: risk-analytics-team
domain: markets
tags: [var, market-risk, regulatory]
dependencies:
  - id: ARCH-002
    type: constrained-by
---

## Intent
Por qué existe esta spec, en dos o tres frases.

## Definition
La regla, la decisión o el comportamiento.

## Acceptance Criteria
- [ ] Un criterio que se pueda comprobar.

## Evidence
Qué la respalda: tests, normativa, validación.

Relaciones

Lo que convierte ficheros en un grafo

Una spec aislada vale poco. Cuando declara de qué depende, una herramienta puede responder qué se rompe si cambia. Las relaciones derivadas las calcula el grafo: no se escriben a mano.

RelaciónSignificadoUso típico
implementsRealiza una spec de nivel superiorFEAT → PROD · FLOW → PROC
constrained-byDebe respetar las restricciones de otraDOM → ARCH · FEAT → DOM
extendsAñade detalle dentro de la misma capaDOM-002 → DOM-001
uses-data-fromConsume datos definidos en otra specFEAT → DOM
activatesConocimiento que se inyecta en el trabajoWRK-SPEC → DOM, ARCH
equipsCapacidad agéntica que se inyecta en el trabajoWRK-SPEC → SKILL, HARN
loadsSkills que un agente puede invocarAGT → SKILL
verifiesUn eval comprueba una skill, un agente, un harness o un flujoEVAL → SKILL, AGT, HARN
requiresNecesita una herramienta determinista, con rango semverSKILL requires TOOL >=0.6 <1.0
mechanized-byUna regla concreta de una herramienta aplica la normaRULE → TOOL rule broken-ref
distilled-from · derivadaLa spec se reconcilió desde un fragmentoDOM → FRAG
derived-from · derivadaEntradas fijadas de una proyecciónPROJ → DOM@1.2.0
runs · derivadaSale de los pasos de un flujoFLOW → SKILL, AGT, TOOL
supersedesSustituye a otra specNueva versión → deprecada
depends-onDependencia genéricaCualquier capa
Checklist

Antes del pull request

Cabecera

  • El id sigue el patrón TIPO-AREA-NNN
  • La layer corresponde al type
  • status y confidence tienen valores válidos
  • owner es un equipo o una persona real

Dependencias

  • Cada id referenciado existe
  • No hay dependencias circulares
  • La relación tiene sentido: una FEAT no restringe a una ARCH
  • Si es de trabajo, se respeta la regla de los ejes

Cuerpo

  • Intent explica el porqué, no el qué
  • Los criterios de aceptación se pueden comprobar
  • Evidence cita fuentes reales

Validación

  • spec-graph validate pasa
  • spec-graph orphans no señala la spec nueva
  • Si modificas una existente, sube la versión
  • Si la sustituyes, marca la antigua como deprecated
CLI

Referencia de comandos

Los comandos de la herramienta que valida y consulta el grafo, agrupados por lo que se quiere hacer.

ComandoQué hace
SALUD
validateComprueba todas las specs: campos obligatorios, referencias, valores permitidos y coherencia de relaciones. Es el que bloquea el PR.
orphansLista las specs sin referencias entrantes ni salientes. Avisa, no bloquea.
statsCifras del grafo: specs por capa, reparto de confianza y densidad de relaciones.
filterFiltra por capa, etiqueta, nivel de confianza derivado o specs caducadas.
NAVEGACIÓN
context <id> --depth NCalcula el contexto de una spec siguiendo sus dependencias. Base de la activación transitiva.
impact <id>Lista todo lo que depende de una spec: qué se rompe si la cambias.
upgrade-impactCompara dos referencias de Git e indica qué trabajo queda afectado por los cambios de conocimiento.
path <a> <b>Camino más corto entre dos specs.
ACTIVACIÓN
resolve <manifiesto>Resuelve un manifiesto con unos parámetros y muestra qué activaría y qué sugeriría.
new-task <tipo>Resuelve el manifiesto y escribe una WRK-SPEC con la activación ya congelada.
bootstrap <wrk-spec>Compone el plan de arranque de una WRK-SPEC congelada. En simulación planifica sin escribir.
FLUJOS
new-run <flow-id>Lanza un flujo: valida los parámetros y escribe la WRK-SPEC, el WRK-PLAN y una WRK-TASK por paso.
run-status <wrk-spec>Paso actual, intentos, decisiones humanas abiertas y tomadas, y coste de una ejecución. Solo lectura.
DERIVADOS Y DISTRIBUCIÓN
check-projectionsDetecta proyecciones obsoletas, desviadas o sin bloqueo. En modo estricto hace fallar el build.
lock <proj-id>Escribe o refresca el bloqueo de una proyección a partir de sus refs y sus ficheros.
vendor <proj-id>Materializa una proyección de tipo copia, byte a byte y con su clausura.
render <proj-id>Ejecuta el renderizador fijado de una proyección de tipo entregable y escribe su bloqueo.
bundle --manifestResuelve un manifiesto y emite su clausura como paquete reproducible.
EVIDENCIA E INTEROPERABILIDAD
fragmentsLista los fragmentos con su estado y las specs en que se destilaron.
export-okfExporta las specs como paquete OKF v0.2 conservando la cabecera completa de cada spec.
import-okf <paquete>Incorpora un paquete OKF externo como specs gobernadas, conservando su cabecera original.
Glosario

Vocabulario esencial

TérminoÁmbitoQué significa
specBaseFichero Markdown con cabecera YAML que recoge una pieza de conocimiento, de capacidad, de trabajo o una decisión. Es la unidad mínima de KND.
frontmatterBaseLa cabecera YAML, delimitada por dos líneas de tres guiones. Guarda los campos que leen las herramientas: id, type, layer, status, confidence, version, owner y dependencias.
ejeBaseCada una de las cuatro familias de specs: Conocimiento, Agéntico, Trabajo y Gobierno. No se solapan entre sí.
capa (layer)BaseDivisión dentro de un eje. En Conocimiento: architecture, domain, product, feature y documentation.
grafoBaseLa red de specs unidas por sus dependencias. Sobre ella se calcula el impacto de un cambio, las huérfanas y el contexto de una tarea.
activarActivaciónLlevar a un ítem de trabajo las specs de conocimiento que necesita, mediante el campo activates.
equiparActivaciónLo mismo en el eje Agéntico: skills, agentes y perfil de harness mediante el campo equips, siempre con versión fijada.
manifiestoActivaciónSpec que, para un tipo de tarea y unos parámetros, resuelve sola qué activar y qué equipar, para no decidirlo a mano en cada entrega.
congelar (frozen)ActivaciónFijar sin vuelta atrás qué specs y qué versiones usó una entrega. Los cambios posteriores no reescriben lo que se ejecutó.
presupuesto de activaciónActivaciónCuántas specs conviene activar según el nivel: de 5 a 10 en una WRK-SPEC, de 3 a 7 en un plan, de 2 a 5 en una tarea.
clausuraDistribuciónTodas las specs alcanzables desde un punto siguiendo dependencias. Es lo que debe llevar un paquete para valerse por sí mismo.
consolidarCicloDevolver al conocimiento lo aprendido en una entrega: ADR nuevos, specs de dominio actualizadas, patrones recogidos.
gateFlujosPunto de un flujo donde se decide si un paso ha ido bien: el veredicto de una herramienta, un eval, una decisión humana o nada.
veredictoFlujosSalida de una herramienta que dictamina si algo pasa. La skill lo traslada tal cual, sin recalcularlo.
harnessAgentesPerfil de ejecución de un agente expresado como política: herramientas disponibles, guardarraíles y enrutado. Es una spec, no un ajuste suelto.
run (ejecución)FlujosUna ejecución concreta de un flujo: artefactos de trabajo más un registro de eventos al que solo se añaden líneas.
nivel de confianzaConfianzaunverified, machine-confirmed o human-reviewed. No se guarda: se calcula al consultar, según quién haya verificado la spec.
techo de confianzaConfianzaLa confianza máxima que permite declarar la evidencia disponible. Puede limitar, nunca subir.
huérfanaSaludSpec sin referencias entrantes ni salientes. No siempre es un error, pero merece revisión.
impactoSaludTodo lo que se ve afectado al cambiar una spec. Se consulta antes de tocarla.
proyecciónDerivadosContenido generado a partir de specs con versión fijada: una copia, una composición, un entregable o un conjunto de datos recalculado.
fragmentoDerivadosCaptura inmutable y fechada de evidencia en bruto: una reunión, un informe, una transcripción. Se destila en specs; nunca se activa.
